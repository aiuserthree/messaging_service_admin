# 관리자 시스템 문서

## 메뉴 구조도

### 대시보드
#### 최근 현황
- **KPI 카드**: 금일/주간/월간 매출 금액, 실 발송 금액, 채널별 발송 건수, 성공 수, 실패율 등 주요 지표 제공
- **최대 매출 회원 조회**: 금일/주간/월간 발송량 가장 많은 회원 계정, 발송 건수, 채널별 발송 성공 건수, 선불 충전 금액 등 주요 지표 제공

### 발송관리
#### 전체 발송 내역
- **발송 목록 조회**: 전체 회원의 메시지 발송 내역을 기간/상태/유형별로 검색 및 필터링
- **발송 상세 정보**: 특정 발송 건의 상세 내역(수신자별 성공/실패 사유, 메시지 내용 등) 확인

### 회원 관리
#### 회원 목록
- **회원 조회**: 전체 회원(개인/기업) 목록 조회 및 회원유형, 가입일, 상태별 검색
- **회원 상세**: 회원의 기본정보, 발신번호, 결제내역, 발송이력 등 상세 정보 조회. 하위탭으로 제출서류 바로 확인 가능

#### 회원 가입 관리
- **가입 승인 요청**: 기업회원 가입 신청 목록 조회 및 첨부 서류(사업자등록증 등) 검토. 승인 처리 및 반려 사유 입력. 승인 완료 시 자동 안내 메일 발송. 서류 보완 요청 가능

#### 회원 정보 관리
- **회원 정보 수정**: 회원의 기본 정보(이름, 연락처, 이메일, 서브어카운트 등) 수정. 서류(신분증 등) 변경시 관리자 인증 절차 필요
- **회원 상태 변경**: 회원 계정 활성화/비활성화/휴면/탈퇴 처리 및 상태 변경 사유 기록. 종속데이터 확인 후 처리
- **서브어카운트 신청**: 기업 회원의 서브어카운트 신청 목록 조회 및 승인 처리 *(기능 검토 필요)*
- **서류 목록 조회**: 회원이 제출한 사업자등록증, 신분증, 각종 인증·관계서류 리스트 열람 (암호화 저장)
- **서류 상세 조회**: 선택한 회원이 제출한 서류 뷰어 제공. 접근로그 자동 기록
- **서류 인증 처리**: 제출서류의 진위·적합성 심사, 승인·반려·보완요청 입력. 특정 관리자(심사자)만 접근 가능. 심사이력 기록

### 주소록 관리
#### 주소록 목록
- **전체 주소록 조회**: 회원별 등록된 모든 고객 주소록을 리스트로 확인, 그룹별/기간별 검색 제공. 가운데 번호 마스킹 처리 필수.
- **주소록 상세/편집**: 선택한 주소록 내 수신자 등록, 수정, 삭제 및 그룹 이동 등 세부 편집 기능

#### 대량 주소록 관리
- **엑셀 업로드**: 대량 수신자 주소록을 엑셀 파일로 한 번에 등록 및 데이터 검증 처리
- **일괄 삭제/수정**: 여러 주소록 또는 다수 수신자 데이터의 일괄 변경 및 삭제 처리

#### 수신거부 관리
- **수신거부 목록**: 전체 주소록의 수신거부 등록된 전화번호 목록 조회 및 검색

### 발신번호 관리
#### 발신번호 인증
- **인증 요청 관리**: 회원의 발신번호 인증 요청 목록 조회 및 첨부 서류 확인. 발신번호 인증 심사 후 승인 또는 반려 처리 및 사유 입력

### 결제 및 정산
#### 결제 관리
- **결제 내역 조회**: 회원별 결제 내역 전체 조회 및 결제 방법, 결제 상태별 검색
- **결제 상세**: 결제 건별 상세 정보(금액, 결제수단, 영수증) 조회 및 환불/취소 이력

#### 정산 관리
- **월별 정산 현황**: 월별 매출, 발송 건수, 정산 금액 통계 및 회원별 과금 내역, 미수금 관리

#### 환불 관리
- **환불 요청 목록**: 탈퇴 회원의 환불 요청 목록 조회 및 환불 사유, 요청 금액, 처리 상태 확인. 환불 승인. *(기능 검토 필요)*
- **추가 증빙 서류 조회**: 탈퇴 회원이 제출한 서류 뷰어 제공. 접근로그 자동 기록. *(기능 검토 필요)*

### 고객 지원
#### 문의 관리
- **문의 목록**: 회원의 1:1 문의 및 고객센터 문의 목록 조회, 문의 유형/처리 상태별 검색
- **문의 답변**: 문의 내용 확인 및 답변 작성, 답변 완료 시 회원에게 자동 알림

#### 공지사항
- **공지사항 목록**: 시스템 공지사항 목록 조회 및 중요도, 게시 상태별 관리
- **공지사항 등록/수정**: 공지사항 신규 작성 및 수정, 게시 기간 및 팝업 노출 여부 설정

#### FAQ 관리
- **FAQ 목록**: 자주 묻는 질문 목록 조회 및 검색, 카테고리별 관리
- **FAQ 등록/수정**: FAQ 신규 등록 및 내용 수정, 노출 순서 및 카테고리 설정

### 스팸·제재 관리
#### 스팸 신고 내역
- **신고 목록 조회**: 접수된 스팸 신고 내역 실시간 확인, 신고 유형·회원·상태별 검색·분류
- **신고 상세/연계 분석**: 각 신고건의 상세 내용, 발송 메시지, 회원 발송 이력/패턴 연동 분석

#### 계정 제재 관리
- **즉시 계정 제재·정지 처리**: 위반 사실 확인 후 계정(서비스) 정지·발송 중단·경고, 사유 입력, 알림 발송
- **제재 이력 / 해제 / 소명처리**: 제재 처리 이력 조회, 일시정지 해제 및 회원 소명 확인, 기록 보관

### 시스템 설정
#### 환경 설정
- **서비스 정책 설정**: 발송 제한 정책, 요금 정책, 가입 정책 등 시스템 전반의 운영 정책 관리
- **알림 설정**: 관리자 알림 수신 조건 및 방법 설정, 중요 이벤트 알림 관리

#### API 관리
- **API 키 발급**: 회원별 API 키 생성 및 관리, API 사용 권한 설정
- **API 사용 내역**: 회원별 API 호출 내역 및 사용량 통계, API 오류 로그 조회

#### 코드 관리
- **공통 코드 관리**: 시스템에서 사용하는 공통 코드 등록/수정/삭제(메시지 유형, 실패 사유 등)

### 보안 및 감사
#### 접근 로그
- **관리자 접근 이력**: 관리자 계정의 로그인 이력 및 접속 정보 조회(접속 IP, 시간, 성공/실패)
- **회원 접근 이력**: 회원의 로그인 이력 및 이상 접근 패턴 모니터링(다중 로그인, 해외 IP 등)

#### 작업 로그
- **데이터 변경 이력**: 중요 데이터 변경 이력 조회(변경 전/후 데이터, 작업자, 작업 시간 기록)
- **권한 변경 이력**: 관리자 및 회원의 권한 변경 이력 조회 및 권한 부여/회수 담당자 기록

#### 보안 정책
- **IP 접근 제어**: 관리자 페이지 접근 허용 IP 등록 및 관리, IP 화이트리스트/블랙리스트 설정
- **비밀번호 정책**: 비밀번호 복잡도, 변경 주기, 재사용 제한 등 설정 및 관리자/회원별 차등 적용

## Use Case 목록

### UC-DASH-01: KPI 현황 조회
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 대시보드에서 주요 발송/매출 KPI를 조회한다.
- **사전조건**:
  1. 관리자가 관리자 계정으로 로그인되어 있다.
  2. 발송/결제 통계 데이터가 수집되고 있다.
- **사후조건**:
  1. 성공 시, 금일/전일/전주 대비 발송 건수, 성공률, 실패율, 예약 건수 등 지표가 카드로 표시된다.
  2. 성공 시, 관리자는 KPI를 기반으로 이상 징후 여부를 판단할 수 있다.
  3. 실패 시, 통계 집계 실패 또는 데이터 조회 오류 메시지가 표시된다.
- **기본흐름**:
  1. 관리자가 로그인 후 '대시보드' 메뉴에 접속한다.
  2. 시스템이 기본 기간(예: 당일 기준)의 KPI 데이터를 조회한다.
  3. 화면에 발송 건수, 성공률, 실패율, 예약 건수, 주요 매출 지표가 카드/그래프 형태로 표시된다.
  4. 관리자가 기간(일/주/월) 또는 서비스 구분(일반 문자/선거 문자 등)을 변경한다.
  5. 시스템이 변경된 조건에 맞게 KPI를 재계산하여 갱신한다.
- **대체흐름**:
  1. 관리자는 특정 회원 또는 특정 캠페인 기준으로 KPI를 Drill-down 조회할 수 있다.
  2. 관리자는 KPI 위젯(카드/차트)을 ON/OFF 하거나 위치를 개인 설정으로 변경할 수 있다.
- **예외흐름**:
  1. 데이터 수집/집계 배치가 실패한 경우 "일부 지표가 최신이 아닐 수 있습니다." 경고 메시지가 표시된다.
  2. 권한이 제한된 운영자는 특정 민감 지표(매출, 특정 회원 KPI 등)를 볼 수 없고, 접근 제한 메시지가 표시된다.

### UC-DASH-02: 최대 매출 회원 조회
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 분석기간 내 충전 금액 별 고객 목록을 조회한다.
- **사전조건**:
  1. 관리자가 관리자 계정으로 로그인되어 있다.
  2. 발송/결제 통계 데이터가 수집되고 있다.
- **사후조건**:
  1. 성공 시, 충전 금액 별 회원 목록이 나열된다.
  2. 성공 시, 관리자는 회원 상세 정보 조회 화면으로 이동할 수 있다.
  3. 실패 시, 통계 집계 실패 또는 데이터 조회 오류 메시지가 표시된다.
- **기본흐름**:
  1. 관리자가 대시보드 화면 하단/사이드의 '회원별 충전 내역' 항목을 확인한다.
  2. 시스템이 최근 총 충전 금액 기준으로 총 충전 금액, 발송 성공 건수, 채널별 성공/실패 건수 상태를 리스트로 표시한다.
  3. 관리자가 특정 행을 클릭하면 '회원 상세 정보 조회' 화면(회원 관리 화면)으로 이동한다.
- **대체흐름**:
  1. 관리자가 표시 개수(예: 10건/50건) 또는 기간(최근 1시간/1일)을 변경한다.
- **예외흐름**:
  1. 분석 기간 내 선불 충전한 고객이 없는 경우 '데이터가 존재하지 않습니다' 메시지가 표시된다.

### UC-SEND-01: 전체 발송 내역 조회
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 전체 회원의 메시지 발송 내역을 기간/상태/유형별로 검색 및 필터링한다.
- **사전조건**:
  1. 관리자가 시스템에 로그인되어 있다.
  2. 발송 데이터가 1건 이상 존재한다.
- **사후조건**:
  1. 성공 시, 전체 발송 내역이 리스트로 표시된다.
  2. 성공 시, 검색 및 필터링이 적용된다.
  3. 실패 시, 데이터 조회 오류 메시지가 표시된다.
- **기본흐름**:
  1. 관리자가 대시보드의 '전체 발송 내역' 탭 또는 위젯을 선택한다.
  2. 시스템이 전체 발송 내역 목록을 조회하여 표시한다(회원명, 발송일시, 수신자 수, 성공/실패 건수, 상태 등).
  3. 관리자가 검색 조건(회원, 기간, 상태, 유형 등)을 입력한다.
  4. 시스템이 조건에 맞는 발송 내역을 재조회하여 표시한다.
  5. 관리자가 특정 발송 건을 선택하여 상세 정보 화면으로 이동한다.
- **대체흐름**:
  1. 관리자는 발송 내역을 엑셀 파일로 다운로드할 수 있다.
  2. 관리자는 다중 조건으로 복합 검색을 수행할 수 있다.
- **예외흐름**:
  1. DB 연결 장애 발생 시 "데이터베이스 연결에 실패했습니다." 메시지가 표시된다.
  2. 검색 조건에 해당하는 발송 내역이 없을 경우 "조건에 맞는 발송 내역이 없습니다." 안내 메시지가 표시된다.

### UC-SEND-02: 발송 상세 정보 조회
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 특정 발송 건의 상세 내역을 조회한다.
- **사전조건**:
  1. 관리자가 전체 발송 내역 또는 최근 발송 내역에서 특정 발송 건을 선택한다.
  2. 해당 발송 데이터가 시스템에 존재한다.
- **사후조건**:
  1. 성공 시, 발송 건의 상세 정보(수신자별 성공/실패 사유, 메시지 내용, 발송 시간 등)가 표시된다.
  2. 실패 시, 데이터 조회 오류 메시지가 표시된다.
- **기본흐름**:

  1. 관리자는 다중 조건(이름+아이디+가입기간)으로 복합 검색을 수행할 수 있다.
  2. 관리자는 검색 결과를 엑셀 파일로 다운로드할 수 있다.
- **예외흐름**:
  1. DB 연결 장애 발생 시 "데이터베이스 연결에 실패했습니다. 잠시 후 다시 시도해주세요." 메시지가 표시된다.

  2. 성공 시, 하위탭으로 제출서류를 바로 확인할 수 있다.

- **대체흐름**:

- **예외흐름**:

### UC-MEMBER-03: 회원 가입 승인 요청 조회 및 검토
- **Actors**: 예비회원, 관리자, 시스템
- **개요**: 관리자가 기업회원의 가입 신청 목록을 조회하고 첨부 서류를 검토한다.
- **사전조건**:
  1. 예비회원이 가입 신청을 완료하고 필요 서류를 제출한다.
  2. 가입 신청이 미승인 상태로 등록되어 있다.
- **사후조건**:
  1. 성공 시, 가입 승인 요청 목록이 화면에 표시된다.
  2. 성공 시, 관리자는 첨부 서류(사업자등록증 등)를 확인할 수 있다.
  3. 실패 시, 데이터 조회 오류 메시지가 표시된다.
- **기본흐름**:

  2. 예비회원이 가입 신청을 완료한다.
  3. 관리자가 '회원 관리' → '회원 가입 관리' → '가입 승인 요청' 메뉴를 선택한다.
  4. 시스템이 미승인 상태의 가입 신청 목록을 표시한다.
  5. 관리자가 특정 신청 건을 선택하여 상세 정보와 첨부 서류를 확인한다.
  6. 관리자는 서류의 진위 여부를 수기로 확인한다.
- **대체흐름**:
  1. 관리자는 여러 신청 건을 동시에 선택하여 일괄 검토할 수 있다.
  2. 서류가 불명확한 경우 보완 요청을 할 수 있다.
- **예외흐름**:
  1. 서류가 첨부되지 않은 경우 "필수 서류가 첨부되지 않았습니다." 안내 메시지가 표시된다.
  2. 서류 파일이 손상되었거나 열리지 않는 경우 "서류 파일을 열 수 없습니다." 오류 메시지가 표시된다.

### UC-MEMBER-04: 회원 가입 승인/반려 처리
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 가입 신청을 검토한 후 승인 또는 반려 처리한다.
- **사전조건**:
  1. 관리자가 가입 승인 요청을 검토 완료했다.
  2. 가입 신청이 미승인 상태로 존재한다.
- **사후조건**:
  1. 성공(승인) 시, 회원 계정이 활성화되고 안내 메일이 발송된다.
  2. 성공(반려) 시, 반려 사유가 예비회원에게 이메일로 전달된다.
  3. 실패 시, 처리 오류 메시지가 표시된다.
- **기본흐름**:
  1. 관리자가 가입 승인 요청 목록에서 처리할 신청 건을 선택한다.
  2. 관리자가 첨부 서류와 입력 정보를 확인한다.
  3. 서류와 정보가 올바른 경우, 관리자는 '승인' 버튼을 클릭한다.
  4. 시스템이 회원 정보를 데이터베이스에 등록하고 계정을 활성화한다.
  5. 시스템이 예비회원에게 승인 완료 안내 이메일을 자동으로 발송한다.
  6. 화면에 "가입 승인이 완료되었습니다." 메시지가 표시된다.
- **대체흐름**:
  1. 서류나 정보가 부적합한 경우, 관리자는 '반려' 버튼을 클릭한다.
  2. 관리자는 반려 사유를 입력한다.
  3. 시스템이 예비회원에게 반려 사유를 포함한 안내 이메일을 발송한다.
  4. 관리자는 서류 보완 요청을 선택하여 재신청을 안내할 수 있다.
- **예외흐름**:
  1. 다음과 같은 경우 관리자는 가입 요청을 거절한다.
     - 서류 식별이 불가할 경우
     - 서류가 잘못 첨부된 경우
     - 이용약관에 따라 재가입이 불가된 명의인 경우
  2. 이메일 발송 실패 시 "승인 완료되었으나 안내 메일 발송에 실패했습니다." 경고 메시지가 표시된다.

  2. 성공(반려) 시, 반려 사유가 기록되고 회원에게 보완 요청이 전달된다.

  4. 실패 시, 처리 오류 메시지가 표시된다.
- **기본흐름**:
  1. 관리자가 '회원 관리' → '서류 관리' → '서류 인증 처리' 메뉴를 선택한다.
  2. 시스템이 미승인 상태의 서류 목록을 표시한다.
  3. 관리자가 심사할 서류를 선택한다.
  4. 관리자가 서류 내용을 확인하고 진위 여부를 판단한다.
  5. 서류가 적합한 경우, 관리자는 '승인' 버튼을 클릭한다.
  6. 시스템이 서류 상태를 '승인'으로 변경하고 데이터베이스에 반영한다.
  7. 시스템이 회원에게 승인 완료 알림을 발송한다.
  8. 화면에 "서류 승인이 완료되었습니다." 메시지가 표시된다.
- **대체흐름**:
  1. 서류가 부적합한 경우, 관리자는 '반려' 버튼을 클릭한다.
  2. 관리자는 반려 사유 및 보완 요청 사항을 입력한다.
  3. 시스템이 서류 상태를 '반려'로 변경하고 회원에게 보완 요청 알림을 발송한다.
- **예외흐름**:
  1. 관리자가 심사 권한이 없을 경우 "서류 심사 권한이 없습니다." 오류 메시지가 표시되고 접근이 차단된다.
  2. 서류 파일이 손상되어 확인이 불가한 경우 "서류를 확인할 수 없습니다. 재제출을 요청하세요." 메시지가 표시된다.
  3. 이미 심사 완료된 서류를 재심사하려 할 경우 "이미 처리된 서류입니다." 안내 메시지가 표시된다.

### UC-ADDRESS-01: 전체 주소록 조회
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 회원별로 등록된 모든 고객 주소록을 리스트로 조회한다.
- **사전조건**:
  1. 관리자가 시스템에 로그인한다.
  2. 주소록 데이터가 1건 이상 등록되어 있다.
- **사후조건**:
  1. 성공 시, 회원별 주소록 목록이 화면에 표시된다.
  2. 성공 시, 그룹별, 기간별 검색 및 필터링이 가능하다.
  3. 실패 시, DB 조회 오류 메시지가 표시된다.
- **기본흐름**:
  1. 관리자가 '주소록 관리' → '주소록 목록' → '전체 주소록 조회' 메뉴를 선택한다.
  2. 시스템이 전체 회원의 주소록 목록을 조회하여 화면에 표시한다.
  3. 화면에 회원명, 주소록명, 그룹명, 수신자 수, 등록일, 최종 수정일이 나타난다.
  4. 관리자가 검색 조건(회원명, 주소록명, 그룹명, 등록 기간)을 입력한다.
  5. 시스템이 조건에 맞는 주소록 목록을 재조회하여 표시한다.
  6. 관리자가 특정 주소록을 선택하여 상세 화면으로 이동한다.
- **대체흐름**:
  1. 관리자는 다중 조건(회원명+그룹명+기간)으로 복합 검색을 수행할 수 있다.
  2. 관리자는 검색 결과를 엑셀 파일로 다운로드할 수 있다.
- **예외흐름**:
  1. DB 연결 장애 발생 시 "데이터베이스 연결에 실패했습니다. 잠시 후 다시 시도해주세요." 메시지가 표시된다.
  2. 검색 조건에 해당하는 주소록이 없을 경우 "조건에 맞는 주소록이 없습니다." 안내 메시지가 표시된다.

### UC-ADDRESS-02: 주소록 상세 조회 및 편집
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 선택한 주소록 내 수신자 정보를 조회하고 등록, 수정, 삭제 등 편집 작업을 수행한다.
- **사전조건**:
  1. 관리자가 주소록 목록에서 특정 주소록을 선택한다.
  2. 해당 주소록이 데이터베이스에 존재한다.
- **사후조건**:
  1. 성공 시, 주소록 내 수신자 목록 및 그룹 정보가 화면에 표시된다.
  2. 성공 시, 수신자 등록, 수정, 삭제, 그룹 이동이 처리된다.
  3. 실패 시, 접근 권한 오류 또는 데이터 오류 메시지가 표시된다.
- **기본흐름**:
  1. 관리자가 주소록 목록에서 대상 주소록을 선택한다.
  2. 시스템이 주소록 상세 정보(주소록명, 그룹 목록, 수신자 목록)를 조회하여 표시한다.
  3. 화면에 수신자 이름, 전화번호, 그룹, 등록일이 나타난다.
  4. 관리자가 '수신자 추가' 버튼을 클릭하여 신규 수신자를 등록한다.
  5. 관리자가 기존 수신자를 선택하여 정보를 수정하거나 삭제한다.
  6. 관리자가 수신자를 다른 그룹으로 이동한다.
  7. 시스템이 변경 사항을 데이터베이스에 반영한다.
- **대체흐름**:
  1. 관리자는 여러 수신자를 일괄 선택하여 그룹 이동 또는 삭제를 수행할 수 있다.
  2. 관리자는 주소록 내 수신자 목록을 엑셀 파일로 다운로드할 수 있다.
- **예외흐름**:
  1. 중복된 전화번호를 등록하려 할 경우 "이미 등록된 전화번호입니다." 안내 메시지가 표시된다.
  2. 필수 입력값(전화번호)이 누락된 경우 "필수 항목을 입력해주세요." 메시지가 표시된다.

### UC-ADDRESS-03: 대량 주소록 엑셀 업로드
- **Actors**: 관리자, 시스템
- **개요**: 관리자가 엑셀 파일을 업로드하여 대량의 수신자 주소록을 한 번에 등록한다.
- **사전조건**:
  1. 관리자가 주소록 관리 권한을 보유하고 로그인한다.

- **사후조건**:
  1. 성공 시, 엑셀 파일의 수신자 데이터가 데이터베이스에 등록된다.
  2. 성공 시, 데이터 검증 결과(성공/실패 건수)가 표시된다.

- **기본흐름**:
  1. 관리자가 '주소록 관리' → '대량 주소록 관리' → '엑셀 업로드' 메뉴를 선택한다.

  3. 관리자가 '업로드' 버튼을 클릭한다.
  4. 시스템이 엑셀 파일을 읽고 데이터 형식을 검증한다.
  5. 시스템이 유효한 데이터를 데이터베이스에 등록한다.
  6. 화면에 "총 N건 중 성공 M건, 실패 K건" 결과 메시지가 표시된다.
  7. 실패 건이 있을 경우, 오류 내역을 다운로드할 수 있다.
- **대체흐름**:
  1. 관리자는 엑셀 템플릿을 다운로드하여 양식에 맞게 데이터를 작성할 수 있다.
  2. 시스템은 중복 전화번호를 자동으로 제거하거나 병합 옵션을 제공할 수 있다.
- **예외흐름**:
  1. 엑셀 파일 형식이 잘못된 경우 "지원되지 않는 파일 형식입니다. xlsx 또는 xls 파일을 업로드해주세요." 메시지가 표시된다.
  2. 필수 컬럼(전화번호)이 누락된 경우 "필수 컬럼이 없습니다. 템플릿을 참고하여 파일을 수정해주세요." 메시지가 표시된다.
  3. 전화번호 형식이 잘못된 경우 해당 행은 실패 처리되고 오류 내역에 표시된다.

### UC-CS-01: 문의 목록 조회

### UC-SPAM-03: 계정 제재·이용정지 처리
- **Actors**: 관리자, 시스템
- **개요**: 스팸 신고가 확인된 회원에 대해 관리자가 계정 정지, 발송중단, 서비스 제한 등의 제재를 즉시 실행한다.
- **사전조건**:
  1. 스팸 신고를 확인하여 위반 사실이 명확히 드러남.
- **사후조건**:
  1. 성공 시, 해당 회원 계정이 정지 또는 제한되고 결과 이력이 기록됨.
  2. 회원 및 관련 담당자에게 제재 사실 알림 전송.
  3. 실패 시, 처리 오류, 권한 부족 안내.
- **기본흐름**:
  1. 관리자가 대상 회원의 정지 또는 이용제한 요청 버튼 클릭.
  2. 시스템이 정지 유형(일시정지, 영구정지, 발송만 제한 등) 및 사유 입력, 제재 기간 팝업을 표시.
  3. 관리자가 유형, 사유 입력 후 확인 시 즉시 반영.
  4. 시스템이 계정/서비스 상태를 변경, 관리자 알림/회원 알림 발송.
  5. 제재 처리 이력을 저장.
- **대체흐름**:
  1. 제재 전 임시 경고, 소명 요청(회원 변명 제출)을 할 수도 있음.
- **예외흐름**:
  1. DB 오류 등으로 계정 상태 적용 미처리시 안내.

### UC-SPAM-04: 계정 제재·이용정지 해제
- **Actors**: 관리자, 시스템
- **개요**: 스팸 신고로 제재 처리가 된 회원이 소명 자료를 가져와 해명이 완료되면 관리자는 확인 후 회원의 제재 처리를 해제한다.
- **사전조건**:
  1. 회원이 스팸으로 제재가 됨.
  2. 관리자가 시스템에 로그인되어 있다.
- **사후조건**:
  1. 성공 시, 회원의 제재가 해제되어 회원의 서비스 이용이 가능.
  2. 실패 시, 회원에게 서류 보충하여 재제출 요청
- **기본흐름**:
  1. 회원이 마이페이지/스팸 제재 팝업의 '소명 자료 제출' 버튼 클릭.
  2. 회원이 소명 자료 제출 완료.
  3. 시스템은 관리자에게 서류 제출 알림 발송.
  4. 관리자는 회원이 제출한 서류 조회.
  5. 소명 완료 확인되었을 시 '제재 해제' 버튼 클릭하여 이용 제한 해제.
  6. 제재 처리 이력을 저장.
- **예외흐름**:
  1. DB 오류 등으로 계정 상태 적용 미처리시 안내.
